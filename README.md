# Capability Drift Framework (CDF)

CDF is a parallel framework for measuring horizon-dependent reliability degradation in LLM-based agents. It evaluates how an agent's end-to-end reliability changes as the number of dependent steps in a task (the "horizon", $h$) increases.

For each horizon, CDF measures the fraction of trajectories that complete every step correctly. Tasks use deterministic ground truth, so grading does not depend on an LLM judge. The reference generator uses small arithmetic and digit operations to varyA chain length while keeping individual operations simple.

## Architecture

CDF organizes the workload into three levels:

- **L1 - Task parallelism:** asynchronous workers take independent task/rollout jobs from a shared queue. Bounded concurrency overlaps endpoint wait time and lets workers pick up new jobs as they finish.
- **L2 - Rollout parallelism:** multiple rollouts can be run for the same task. The E2 experiment votes over complete parsed trajectories and compares the measured result with analytic majority and plurality reference curves.
- **L3 - Result aggregation:** trajectory outcomes are mapped to per-horizon counts and first-failure histograms. The partial summaries can be merged with an associative operation, then passed to the metric estimators.

The current experiment scripts collect trajectories first and aggregate them afterward. The aggregation code uses mergeable partials, but the default scripts do not expose a live prefix estimate or run a parallel reduction tree.

## Running Experiments (Synthetic)

The synthetic agent has per-step correctness probability $p_t = p_0 \exp(-\beta t)$. Errors are sticky: once a step is wrong, later steps are also wrong. With $\beta=0$, the agent is memoryless; positive $\beta$ simulates declining per-step reliability. These experiments validate behavior against controlled synthetic ground truth; they are not measurements of real model reliability.

- **E1 - Estimator validation:** evaluates memoryless and degrading synthetic agents, fits drift metrics, and estimates bootstrap confidence intervals.
  ```bash
  PYTHONPATH=. python scripts/run_e1.py
  ```
- **E2 - Parallel rollout voting:** tests $k \in \{1,3,5,9\}$ rollouts and measures how whole-trajectory plurality voting changes success by horizon.
  ```bash
  PYTHONPATH=. python scripts/run_e2.py
  ```
- **E3 - Harness scaling:** measures wall time, speedup, and efficiency across concurrency levels using simulated per-step latency.
  ```bash
  PYTHONPATH=. python scripts/run_e3.py
  ```
Or run all at once:
```bash
PYTHONPATH=. python scripts/run_all.py
```

## Running Real-Model Experiments (OpenAI API)

To run CDF against an OpenAI-compatible endpoint, use `scripts/run_real_model.py`. The parser expects lines formatted as `Step X: <value>`; missing, malformed, or out-of-order steps count as failures from the first unparsed step. The script's default real-model sample size is smaller than the synthetic protocol, so treat its output as a project run unless you explicitly configure and report the sample size and other run settings.

1. Set the required environment variables:
   ```bash
   export CDF_API_KEY="your-api-key"
   export CDF_BASE_URL="https://api.openai.com/v1"  # Optional
   export CDF_MODEL="gpt-4o"                        # Optional
   ```
2. Run the script:
   ```bash
   PYTHONPATH=. python scripts/run_real_model.py
   ```

The current real-model runner sends the full operation sequence in one prompt and requests all intermediate values in one response. It therefore measures end-to-end correctness across task horizons, but it does not issue one dependent API call per step. This distinction matters when comparing its latency or execution pattern with a sequential-call protocol.

### Environment variables in PowerShell

On Windows PowerShell, set variables for the current terminal session with:

```powershell
$env:CDF_API_KEY = "your-api-key"
$env:CDF_BASE_URL = "https://api.openai.com/v1" # Optional
$env:CDF_MODEL = "gpt-4o" # Optional
```

## Configuration & Reproducibility
Central defaults are managed in `cdf/config.py`; experiment scripts may also set their own horizons, sample sizes, or concurrency. Record the script, model/provider, horizon set, tasks per horizon, rollout count, temperature, concurrency, retries, and date with any reported result.

Task ground truth uses the deterministic seed `1000 * h + i`, making task contents reproducible for a given horizon and task index. Synthetic rollouts and bootstrap sampling use random seeds; for exact reproduction, preserve the seed and configuration used by the run.

## Interpretation of Metrics

- **$\lambda$ (Drift Coefficient)**: The fitted rate of exponential decline in end-to-end success, using $S(h) \approx A e^{-\lambda h}$. A larger $\lambda$ means faster decline over the tested horizons. For a memoryless agent with constant per-step success $p$, the ideal model gives $\lambda=-\ln p$.
- **$H_{1/2}$ (Exponential Half-Life)**: Theoretical horizon at which the success probability $S(h)$ halves. $H_{1/2} = \ln(2) / \lambda$.
- **$H^{50}$ (Empirical Half-Life)**: The observed horizon where empirical success crosses $0.5$ via log-linear interpolation.
- **$\delta(h)$ (Excess Drift)**: The difference between the observed log-reliability and the short-horizon exponential baseline. Positive, increasing values indicate the measured curve falls below that baseline; this statistic alone does not identify the cause.
- **Voting Bounds**:
  - **Majority reference $S_{maj}$**: models a pessimistic case where wrong rollouts agree with one another.
  - **Plurality reference $S_{plur}$**: models an optimistic case where incorrect rollouts do not collide. The measured voting curve can be interpreted relative to these assumptions; they are analytical reference cases, not guarantees for every error distribution.

Interpret metrics together with the reliability curve, sample sizes, and confidence intervals. A half-life beyond the largest tested horizon is an extrapolation of the fitted model, while the empirical half-life may be unobserved if the measured curve never crosses 0.5.

## Scope and Limitations

- Synthetic experiments provide known ground truth for checking estimators and concurrency behavior. They do not establish how a particular real LLM will perform.
- Real endpoints can add rate limits, retries, variable latency, and correlated errors; these can change both runtime and measured reliability.
- The reference arithmetic/string tasks isolate horizon effects but do not cover the full range of task difficulty or domain transfer.
- Positive excess drift can be consistent with context degradation, accumulated mistakes, formatting errors, or truncation. Further controlled experiments are needed to separate these causes.
- CDF measures reliability as task horizon grows. It does not by itself establish general intelligence or broad generalization.
